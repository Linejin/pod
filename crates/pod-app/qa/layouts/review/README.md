# 분할 리뷰 중심 캡처 (docs/10 §D5.9, 프리셋 13)

```powershell
foreach ($s in 'review','quiet','islands','mono','warm','access') {
  & tools/visual/capture.ps1 -Output crates/pod-app/qa/layouts/review -Scenes @('review-editor-layout') -Style $s -Layout review
}
```

fixture 장면 `review-editor-layout`(데몬 없음, 100작업/300터미널, task-000에 작은 git 저장소 → 실제 diff; dock에는 아무 패널도 열지 않음 → 레이아웃 전용 Review가 나란히 보기로 열림), 보조 모니터 1440×960 physical @150%(논리 960×640), 다크·라이트.
파일: `<dark|light>-review-editor-layout-<style>-review.png` + UIA 트리. 비교 대상: `docs/design/gallery/images/13-review-<dark|light>.png`.
모든 캡처를 목업과 나란히 놓고 직접 확인했다(2026-11-10).

## 목업과 같은 점

나란히 diff가 주 캔버스, 변경 파일 목록(+/− 수), 오른쪽 의견 열과 “에이전트에 보내기”, 리뷰 머리의 `브랜치 → 기준`, 아래 `터미널 N` 줄과 펼치기/접기, 터미널 타일마다 상태 아이콘 · `에이전트 · 이름` · 상태 문구 · 크게 보기, 응답 필요 타일의 주황 띠, 상태줄 집계.

## 의도한 차이

- **왼쪽 작업 목록**: 목업은 파일 목록만 왼쪽에 있다. 작업을 바꾸면 리뷰가 바뀌어야 해서 작업 목록(상태 아이콘 · 제목 · 브랜치와 상태 수)을 맨 왼쪽에 두고, 파일 목록은 Review 패널 자신의 것을 그대로 쓴다.
- **에이전트 상태·승인 대기는 리뷰 머리**: 목업은 의견 열 아래에 카드로 둔다. 작업 단위로 한 줄(작업 터미널별 상태)과 대기 줄(gate면 승인/거부, gate 없는 질문이면 “응답하기”)로 머리에 모았다. fixture에는 gate가 없어 “응답하기”만 보인다(승인/거부는 `review_qa.rs`).
- **도구 막대**: 목업의 단일 툴바(나란히/한 줄, 이전/다음, 의견, 에이전트에 보내기) 대신 Review 패널의 기존 도구 막대 그대로(기능 동일, 펼치기·줄바꿈·파일 단추 추가). 좁은 논리 폭(960)이라 두 줄로 접힌다.
- **줄바꿈 켜짐**: 나란히 보기에서 Review가 줄바꿈을 함께 켠다(기존 동작) → 좁은 폭에서 코드가 줄바꿈된다. 목업은 1440 논리 폭에서 잘라 보여 준다.
- **터미널 내용 없음**: fixture에는 데몬이 없어 타일이 “연결 끊김 · 다시 연결 중…”이다. 실제 연결은 headless 테스트(`review_qa.rs`)로 확인(작업대 패널 그대로, 재연결 없음).
- **터미널 3개**: fixture 작업마다 터미널이 3개다(최대 4개 도킹, 넘으면 `(+N)`).
- **의견 말풍선(diff 안)**: Review 패널의 기존 의견 표시를 쓴다(이 fixture에는 의견이 없다).
- 제목줄은 작업 공간 공용(목업의 `pod / 작업 / 리뷰` 경로 대신 “작업 공간”).

| `review` (13) | 중립 회색, flat 1px 경계, 선택 행 강조 |
