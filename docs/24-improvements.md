# Pod 개선 과제와 기능 로드맵

작성일: 2026-11-13 · 상태: 검토용 제안 · 대상: Windows 공개 오픈소스 배포

Pod의 우선 개선 과제는 편집 내용 보존, 워커 정리와 상태 저장의 신뢰성, 첫 작업을 시작하고 결과를 검증하는 흐름이다. 기능 측면에서는 기존 worktree·세션·오케스트레이션·리뷰 기능을 연결하여 사용자가 실행 설정과 결과의 근거를 확인하고 작업을 다시 이어갈 수 있게 하는 데 집중한다.

## 1 검토 기준과 상태

- 제품 소스 기준: 로컬 `main e3b4db8`. 설치 전용 worktree `SJin-Choi/pod-signed-installer`의 `ad0003e`는 설치·서명 준비 변경을 포함한다. 이후 원격 main의 기능을 이 소스의 구현 상태로 섞지 않는다.
- Astra 워커 3명이 UI·편집기·성능, 데몬·보안·오케스트레이션, 품질·배포·제품 경험을 독립 검토했다. 주요 편집 유실·잠금·정리 경로와 보안 신고 설정은 추가로 대조했다.
- **코드 확인**은 현재 제어 흐름을 확인했다는 뜻이다. 장애 재현이나 해당 회귀 테스트 통과를 뜻하지 않는다. **검증 제안**은 보장 범위의 공백, **기능 제안**은 기존 기능을 확장하는 요구사항이다.
- 설치 EXE·ZIP 생성과 SHA-256 검증은 [설치 빌드](https://github.com/Linejin/pod/actions/runs/43347742977)에서 성공했다. [후속 원격 CI](https://github.com/Linejin/pod/actions/runs/43354301201)는 Windows·deny·Linux 모두 성공했다. 두 실행은 소스와 검증 범위가 다르며, 패키징 성공을 네이티브 UI·이전 버전 업그레이드 검증으로 해석하지 않는다.
- 아래 과제는 초기 검토 목록이며, 후속 구현 상태는 각 ID와 [작업 실행 기록](25-improvement-execution.md)에 갱신한다. 기능 제안의 담당자·일정·출시 범위는 확정하지 않았다. 과거 검토 문서에서 이미 해결된 문제는 다시 현존 결함으로 집계하지 않는다.

우선순위는 P1(유실·정지 위험 또는 초기 배포의 핵심 흐름), P2(일상 사용과 운영 개선), P3(후속 정비)로 구분한다. 규모 S는 국소 변경, M은 도메인·화면·회귀 검증을 함께 다루는 변경, L은 저장·프로토콜·상호작용 설계가 필요한 변경이다. 개발 기간의 약속은 아니다.

## 2 현재 기능과 확장할 부분

| 현재 제공하는 기능 | 추가로 필요한 사용자 행동 |

| Run·Item·의존관계·Worker·재시도·Gate·메일 | 묶음 실행 전에 계획을 검토하고, 보고 완료와 독립 검증 통과를 구분하기 |
| 동시 워커 수·CPU·메모리·디스크·깊이 제한 | 목표별 시간·시도 예산과 신규 실행 일시정지를 운영하기 |

| Diff·의견·해결·전달·그룹 비교·check·최종 선택 | 검토한 변경 버전을 기억하고, 수정 후 재검토할 부분만 찾기 |
| 외부 파일 변경 감지, 저장 전 stamp 확인, 디스크와 버퍼 비교 | 사용자와 에이전트의 동시 수정을 기준 버전과 함께 병합하기 |
| 탭·커서 복원, 에이전트 세션 찾기·재개, holder 재연결 | 미저장 본문을 복구하고, 마지막 확인 이후의 작업 상황과 복구 선택지 확인하기 |
| Worker 정리 화면과 Task 보관·재개 엔진 | 일반 Task와 Run 전체의 보관·자원 반환 계획을 한곳에서 검토하기 |
| GitHub PR 생성·checks·리뷰·병합 | GitHub 이슈를 확인한 후 작업 요청으로 가져오기 |

관련 자료: [보안 신고](../SECURITY.md), [CI](../.github/workflows/ci.yml), [설치 시험](../tools/installer/test-install.ps1), [실제 LSP 시험](../crates/pod-editor/tests/lsp_lifecycle.rs), [시각 QA의 검증 범위](../tools/visual/README.md), [세션 복원](../crates/pod-editor/src/ui/workspace/session.rs), [편집기 배너](../crates/pod-editor/src/ui/workspace/render_panels.rs).

B20은 1차 결합 검증 조사 중 추가한 과제다. [청크 입력](../crates/pod-status/src/engine/input.rs#L78), [상태·턴 재계산](../crates/pod-status/src/engine.rs#L314), [턴 기반 감독](../crates/podd/src/server/orch_runs/supervisor.rs#L291)을 대조하고 실제 pod_status를 사용하는 진단 시험으로 차이를 확인했다. 이번 B01–B05 수정에 포함하지 않았다.

### F01 첫 작업 시작 안내

**사용자 상황:** worktree나 Pod CLI를 모르는 사용자가 설치 후 첫 에이전트 작업을 시작한다.

- **최소 범위:** 빈 화면에서 Git·선택 에이전트 존재 확인→기존 저장소 선택→새 worktree 위치·기준 브랜치 안내→요청 입력→기존 Task 생성으로 연결한다. 시작 후 상태와 리뷰 위치를 짧게 안내하며 건너뛰기·중단 후 재개를 제공한다.
- **완료 기준:** 정상 환경의 새 사용자가 CLI 문서 없이 작업을 시작하고 diff를 연다. 도구가 없으면 실행 전에 이유와 설치 안내를 본다.
- **제외:** 긴 제품 투어, 에이전트 자동 설치, 로그인 대행, 예제의 자동 실행·커밋. [기획의 MVP 제외](01-plan.md#43-범위-밖-범위-통제)인 온보딩 투어와 구분하며, 제한된 첫 작업 안내도 범위 추가로 검토한다.
- **기반과 선행:** [기존 생성 폼](../crates/pod-app/src/workspace/dialogs.rs#L229), [훅 안내](../crates/pod-app/src/hooks_prompt.rs). F07의 읽기 전용 도구 탐지와 공유한다.

### F02 프로젝트 설정 화면

**사용자 상황:** 새 worktree마다 반복하는 의존성 준비와 개발 서버 실행을 프로젝트별로 설정한다.

- **최소 범위:** worktree 위치, setup 명령·모드, 기본 터미널 탭, archive 명령을 조회하고 개인 override를 편집한다. 저장소 값·개인 값·실제 적용값을 나란히 보여 주고 기존 명령 hash 승인에 연결한다.
- **완료 기준:** CLI와 앱의 유효 설정이 일치한다. 한 절만 override해도 다른 저장소 값은 유지되며, 설정 변경 후 신규 Task에 적용될 값을 미리 본다. 명령 hash가 달라지면 다시 승인을 요구한다.
- **제외:** 새 스크립트 실행 엔진, 패키지 관리자 자동 실행, 저장소 설정 자동 커밋, 개인 override를 이용한 신뢰 경계의 무의식적 우회.
- **기반:** [설정 타입](../crates/pod-protocol/src/session_protocol.rs), [설정과 승인](../crates/podd/src/server/repo_config.rs), [기존 CLI](../crates/pod-cli/src/session.rs). 개인 override UI부터 시작한다.

### F03 에이전트와 모델 실행 프로필

**사용자 상황:** 분석·구현·리뷰용 agent/model 설정을 이름으로 선택하고 결과의 실행 조건을 확인한다.

- **최소 범위:** 로컬 프로필에 agent 종류·실행 파일·인자 배열·지원되는 model/effort 옵션을 저장한다. Task·Group·Worker에서 선택하고 실행 직전 실제 적용값과 출처를 보여 준다. Attempt에는 비밀값을 뺀 설정 snapshot/hash를 기록한다.
- **완료 기준:** 예를 들어 Astra 모델을 요청했을 때 지원되지 않으면 시작 전 명시적으로 알린다. 다른 모델로 조용히 대체하지 않는다. 프로필 수정·삭제 이후에도 과거 적용값은 남고 재시도 시 유지/변경 여부를 선택한다. 공백·한글 경로와 인자 배열이 보존된다.
- **제외:** 공급자 간 동일한 추론 옵션 가정, API 키 복제·기록, 전역 설정 덮어쓰기, 프로필 선택에 따른 권한 완화. 실행 종류를 단순 argv로 바꾸어 기존 Codex 전용 안전 보정을 우회하지 않는다.
- **기반:** [AgentSpec](../crates/pod-protocol/src/protocol.rs), [시작 DTO](../crates/pod-protocol/src/orch_run_protocol.rs), [agent 시작 보정](../crates/podd/src/server/agent_launch.rs), [worker 시작](../crates/pod-cli/src/orch_run.rs). 타입·프로필 snapshot 정책을 먼저 정한다.

### F04 변경 버전에 연결된 검증 결과

**사용자 상황:** 워커의 성공 보고와 실제 검사 통과를 구별하고, 검사한 코드가 현재 결과와 같은지 확인한다.

- **최소 범위:** attempt/generation·Task·commit 또는 작업 스냅샷·명령 ID와 설정 hash·exit code·실행 시각·제한된 로그를 검증 기록으로 연결한다. 보고 완료·미검증·통과·실패·오래된 결과를 구분한다. 기존 Group check를 재사용하고, 검증 통과를 후속 Item 시작 조건으로 선택할 수 있게 한다.
- **완료 기준:** 보고만 제출하면 미검증이다. 검사 후 코드가 바뀌면 기존 결과는 오래됨으로 바뀌며, 다른 generation의 결과를 재사용하지 않는다. 실패·취소·timeout을 성공과 구분한다.
- **제외:** 워커 본문의 “테스트 통과”를 실행 증거로 승격, 임의 저장소 명령 자동 신뢰, 검증 성공을 merge 승인으로 취급.
- **기반과 선행:** [완료 모델](../crates/pod-orch/src/model.rs), [완료 처리](../crates/pod-orch/src/engine/completion.rs), [그룹 check](../crates/pod-protocol/src/orch_protocol.rs). B05·B11 개선, 명령 승인·프로세스 제한·로그 보존 정책이 필요하다.

### F05 워커 묶음 실행 계획 미리보기

**사용자 상황:** 여러 워커가 무엇을 어디에서 실행할지 검토한 뒤 시작한다.

- **최소 범위:** 부작용 없는 계획에 저장소·base·Item과 의존관계·프로필·worktree와 터미널 수·setup 신뢰 상태·자원 대기 이유를 표시한다. 승인한 plan hash를 실행 직전 현재 대상·설정과 대조한다.
- **완료 기준:** 미리보기는 Task·터미널·Attempt를 만들지 않는다. 승인 후 repo/base/setup/profile이 바뀌면 차이를 보여 주고 다시 검토한다. 계획의 순환·누락 의존성을 시작 전에 알린다.
- **제외:** 계획 승인을 이후 merge·권한 확대·추가 명령의 포괄 승인으로 사용, 정확한 대기 시간·비용 예측, worktree를 보안 sandbox라고 표시.
- **기반:** [worker 시작](../crates/podd/src/server/orch_runs/launch.rs), [DAG와 시작 타입](../crates/pod-protocol/src/orch_run_protocol.rs), [게이트 정책](../crates/podd/src/server/orch_runs/gates.rs). F03의 적용 설정을 표시한다.

### F06 Run 시간과 시도 예산

**사용자 상황:** 한 목표에 허용할 시간과 새 시도 수를 정하고, 초과하면 현재 작업은 보존하면서 추가 시작을 멈춘다.

- **최소 범위:** Run별 경과시간·신규 Attempt 수 예산과 경고 임계값, 새 시작 일시정지·계속을 제공한다. 신규 worker·retry·하위 Run admission에 적용하고, 이유와 해제 주체를 기록한다.
- **완료 기준:** 재시작해도 예산과 pause가 유지되고 동시 시작·하위 Run으로 한도를 우회하지 않는다. 기존 worker의 보고·메일·안전한 종료는 가능하다.
- **제외:** 기본 강제 kill, 실행 중 모델 프로세스의 정지 보장, 제공되지 않는 token·비용의 정확한 추정. 금액 한도는 신뢰할 수 있는 usage를 제공하는 공급자에 한해 별도 검토하고 나머지는 미측정으로 표시한다.
- **기반:** [기존 자원 한도](../crates/podd/src/server/orch_limits.rs), [admission](../crates/pod-orch/src/engine/admission.rs), [자원 판정](../crates/pod-orch/src/resource.rs). B02·B03·B05가 선행한다.

### F07 문제 해결 화면과 진단 복사

**사용자 상황:** “실행이 안 됨”, “완료인데 작업 중으로 보임”, “LSP가 안 됨”의 원인을 찾고 이슈 작성에 필요한 정보를 준비한다.

- **최소 범위:** 앱·daemon 버전/연결, holder 상태, ConPTY 출처, Git·선택 agent·gh 경로, 훅 상태와 마지막 확인 시각을 읽기 전용으로 집계한다. 수동 재확인과 비밀 제거된 JSON 미리보기·복사를 제공한다.
- **완료 기준:** 도구 누락·오래된 훅·daemon 미실행을 구분하고 항목별 다음 조치를 제시한다. 진단이 daemon을 새로 시작하거나 설정을 바꾸지 않는다. 토큰·터미널 원문·프로젝트 내용은 기본 출력에서 제외하고 경로 포함 여부도 미리 보여 준다.
- **제외:** 자동 로그 업로드, 자동 수정·훅 재설치·daemon 종료, telemetry 서비스. 지원용 원문 로그 추가는 별도 선택이다.
- **기반:** [서버 상태](../crates/pod-cli/src/commands/server.rs), [훅 점검](../crates/pod-app/src/hooks_prompt.rs), [SSH 진단 UI](../crates/pod-app/src/machines_ui.rs). 기존 개선 목록의 통합 진단 제안을 이 기능에 통합한다.

### F08 미저장 편집과 리뷰 초안 복구

**사용자 상황:** 앱이 종료된 뒤 저장 전 코드 수정과 리뷰 의견을 회수한다.

- **최소 범위:** 변경 버퍼와 비어 있지 않은 의견 초안을 Task별 로컬 checkpoint로 보존한다. 경로·디스크 기준 stamp·의견 위치를 함께 저장하고, 재시작 시 복구·비교·다른 이름 저장·버리기를 제공한다. 보관량과 기간을 정한다.
- **완료 기준:** 강제 종료 후 마지막 checkpoint까지 원문을 회수한다. 디스크 변경·파일 삭제·Task 삭제에서도 자동 덮어쓰기 없이 처리하고, 저장 완료·명시적 폐기 후에는 복구본을 제거한다.
- **제외:** 사용자 파일 자동 덮어쓰기, 클라우드 동기화, 전체 편집 히스토리, 에이전트 대화 복제. 복구본도 소스와 비밀을 포함할 수 있으므로 로컬 보존·폐기 정책을 명시한다.
- **기반과 선행:** [탭·커서 세션](../crates/pod-editor/src/ui/workspace/session.rs), [리뷰 상태](../crates/pod-app/src/review.rs). B01·B06·B07을 먼저 수정한다.

### F09 버전별 리뷰 진행도와 재검토

**사용자 상황:** 많은 파일을 검토하던 중 에이전트가 수정했을 때 새로 바뀐 부분을 우선 확인한다.

- **최소 범위:** 파일별 검토 완료를 diff fingerprint에 연결해 저장한다. 변경 시 검토 후 변경됨으로 전환하고 미검토·재검토 필터와 다음 대상 이동을 제공한다. 지난 확인 이후 비교는 사용자가 만든 checkpoint 하나부터 지원한다.
- **완료 기준:** 동일 내용 refresh는 표시를 유지한다. 내용 변경·rename·삭제와 앱 재시작을 처리하며, 의견 해결과 해당 버전의 검토 완료를 구분한다. 무효화된 검토 표시를 승인 근거로 사용하지 않는다.
- **제외:** 자동 승인·의견 해결, AI의 검토 완료 판정, 모든 과거 스냅샷 영구 보존.
- **기반:** [리뷰 모델](../crates/pod-app/src/review/model.rs), [diff 갱신·의견 제어](../crates/pod-app/src/review/controller.rs). F04와 revision 식별 규칙을 공유하고 B06·B07을 선행한다.

### F10 현재 작업의 파일 본문 검색

**사용자 상황:** 파일명이나 심볼을 몰라도 오류 메시지·설정 키를 worktree 전체에서 찾는다.

- **최소 범위:** 현재 Task의 문자열 검색, 대소문자·경로 포함/제외, 파일별 문맥·줄 번호, 편집기 이동, 취소·결과 상한을 제공한다. 기본 제외 규칙은 기존 색인과 맞춘다.
- **완료 기준:** ignore·이진 파일·한글·큰 파일·검색 중 변경을 처리한다. 이전 query 결과가 새 query를 덮지 않으며 올바른 파일·줄로 이동한다. UI를 막지 않고 취소와 상한을 표시한다.
- **제외:** 여러 저장소 통합 검색, 의미 검색·임베딩, 전체 일괄 치환, 원격 검색 서비스.
- **기반:** [파일명 빠른 열기](../crates/pod-editor/src/ui/quick_open.rs), [LSP 탐색](../crates/pod-editor/src/ui/workspace/lsp_actions.rs). 원격 worktree 검색은 별도 전송·권한 설계 후 검토한다.

### F11 사용자와 에이전트 변경의 3-way 병합

**사용자 상황:** 사용자는 함수 A를, 에이전트는 함수 B를 수정했을 때 양쪽 변경을 보존한다.

- **최소 범위:** 마지막으로 읽은 기준·현재 버퍼·최신 디스크를 비교해 겹치지 않는 변경은 미저장 병합 결과로 제시한다. 겹치는 부분은 내 변경·디스크 변경·직접 편집으로 해결하고 최종 저장 때 stamp를 다시 확인한다.
- **완료 기준:** 서로 다른 줄은 양쪽을 보존하고 같은 줄은 미해결 표시한다. 병합 중 세 번째 외부 변경, 인코딩·BOM·줄 끝, 결과 undo를 검사한다.
- **제외:** 자동 저장, Git branch merge/rebase UI, 바이너리·AI 병합, 모든 파일 버전 보관.
- **기반과 선행:** [외부 변경과 저장](../crates/pod-editor/src/ui/workspace/files.rs), [saved 기준 내용](../crates/pod-editor/src/ui/workspace/buffers.rs). B01·B08·B09와 F08의 보존 정책을 먼저 정리한다.

### F12 작업 복귀 요약과 선택적 복구

**사용자 상황:** 어제 작업으로 돌아오거나 daemon이 재시작된 후, 새 변경과 응답할 일을 확인하고 필요한 실행만 이어간다.

- **최소 범위:** Task의 마지막 확인 시각, 변경 파일, 대기 Gate·질문, 리뷰 전달 대기/실패, 최신 관측 PR check를 요약하고 기존 화면으로 연결한다. Run 복구에서는 holder 상태·이전 보고·worktree 변경·남은 검증과 다시 연결·기다리기·새 Attempt 재시도·사람 인수를 제시한다.
- **완료 기준:** 발생 시각과 관측 시각, 오래된 결과를 구분한다. 살아 있는 holder를 중복 실행하지 않고 선택한 Lost만 새 generation으로 재시도한다. 완료 여부가 불명확한 외부 작업은 자동 재실행하지 않는다.
- **제외:** LLM 요약 비용, 네이티브 채팅·대화 복제, 자동 승인·리뷰 전송, PC 재부팅 후 원래 프로세스나 모델 내부 문맥의 완전 복원 보장.
- **기반과 선행:** [세션 재개](18-session-discovery.md), [holder 재연결](../crates/podd/src/server/lifecycle.rs), [Run 감독](../crates/podd/src/server/orch_runs/supervisor.rs). B05·B10·B11이 선행한다. 단순 복귀 요약과 다중 worker 복구는 두 단계로 구현할 수 있다.

### F13 편집과 리뷰 탐색의 뒤로와 앞으로

**사용자 상황:** 리뷰 줄→함수 정의→참조 위치로 이동한 뒤 원래 검토하던 줄로 돌아간다.

- **최소 범위:** Task별 파일·줄·열·리뷰 side의 탐색 history를 제공한다. 명시적 정의·참조·검색·리뷰 이동만 기록하고 일반 커서 움직임은 제외한다. 닫힌 탭은 기존 열기 경로를 재사용한다.
- **완료 기준:** A:10→A:100→B:20의 역순·정순 복귀가 정확하다. 뒤로 간 뒤 새 이동은 forward를 정리하고 삭제·rename 경로를 안전하게 처리한다. 버튼·키·팔레트 동작이 같다.
- **제외:** 편집 undo 대체, 전체 활동 기록, Task 간 전역 history, 터미널 내부 커서 복원.
- **기반:** [탭 MRU](../crates/pod-editor/src/ui/workspace/tabs.rs), [정의·참조 이동](../crates/pod-editor/src/ui/workspace/lsp_actions.rs), [리뷰에서 편집기로 이동](../crates/pod-app/src/review/controller.rs#L410). B01의 경로 식별 정비와 맞춘다.

### F14 GitHub 이슈에서 작업 만들기

**사용자 상황:** OSS 유지관리자가 이슈 URL을 붙여 넣고 내용을 검토한 뒤 Task로 시작한다.

- **최소 범위:** GitHub URL 또는 현재 repo의 이슈 번호를 기존 gh 인증으로 읽고, 제목·본문을 편집 가능한 요청 초안으로 제공한다. 사용자가 확인한 뒤 Task를 만들고 출처 URL·조회 시각을 남긴다. PR 초안에 참조 삽입은 선택 사항이다.
- **완료 기준:** 인증 필요·권한 없음·삭제된 이슈를 구분한다. 다른 저장소 이슈의 출처를 명시하고 확인 전에는 실행하지 않는다. 본문을 Pod 명령이나 승인으로 해석하지 않는다.
- **제외:** Linear·Jira, 양방향 상태 동기화, 자동 댓글·라벨·담당자·종료, 전체 이슈 백그라운드 수집.
- **기반:** [기존 기획](01-plan.md), [PR와 Forge](15-forge-and-pr.md), [Forge 구현](../crates/pod-forge/src/lib.rs). 읽기 전용 URL 단건 가져오기부터 시작한다.

### F15 일반 작업과 Run의 보관 및 정리 계획

**사용자 상황:** 수동 Task와 큰 Run이 쌓였을 때 코드·검증 자료를 남기고 반환할 자원을 선택한다.

- **최소 범위:** 일반 Task도 기존 protected/review/ready 기준으로 표시한다. Run preview에 active/kept/finished, 미결 질문·Gate, dirty/unpushed, 검증 기록과 실제 정리 대상을 제시한다. 기본은 터미널 자원 반환이며 Task 보관·worktree 삭제는 별개 선택이다. 선택한 보고·검증 manifest·로그의 로컬 bundle은 후속 범위로 둔다.
- **완료 기준:** Run에 속하지 않은 Task도 보이고 작업 중·dirty·unmerged는 기본 bulk 선택에서 제외된다. 실행 직전 새 활동·keep·대상 변경을 재검증한다. 보관 실패 시 정리를 보류하고 보관된 Task를 다시 열 수 있다.
- **제외:** 자동 디스크 청소·기한 후 삭제·일괄 force, 로그인 데이터 삭제, 기본 원격 export. bundle에 포함할 원문과 민감정보를 사용자가 확인한다.
- **기반과 선행:** [현재 worker 정리 UI](../crates/pod-app/src/orch_ui/cleanup.rs), [Task 보관](../crates/podd/src/server/task_archive.rs), [worker release](../crates/podd/src/server/orch_runs/workers.rs). B03·B04·B05·B10을 선행한다.

## 5 권장 실행 순서

| 단계 | 우선 결과 | 진입과 완료 조건 |
|---|---|---|
| A 데이터와 수명 보호 | B01–B05, B06–B11의 유실·복구 경로, 설정 클릭 재현 | 결정적 경합·저장 실패·초안 지연 응답 회귀 시험을 마련하고 현재 동작을 확인한다. 저장·정리 관련 기능은 해당 선행 결함 수정 후 확장한다. |
| B 첫 사용과 재현 가능한 실행 | F01·F02·F03·F07, B12·B14·B16·B17 | 첫 작업→실행 설정 확인→diff 열기→진단 복사 흐름과 설치/제거 검증을 확보한다. 일반 사용자를 대상으로 긴 CLI 설정을 요구하지 않는다. |
| C 결과 검증과 리뷰 | F04·F08·F09, B13·B15·B19 | 사용자 입력 보존, 변경 버전과 검사 결과의 일치, 실제 UI·외부 도구 검증을 확인한다. |
| D 많은 작업의 운영 | F05·F06·F10·F12·F13·F15 | 실행 전 계획, 예산, 안전한 재개·정리를 연결한다. UI 비용은 B18 측정으로 우선순위를 조정한다. |
| E 선택 확장 | F11·F14, F15의 보고 bundle | 병합 보존 정책과 외부 데이터 신뢰 경계를 확인한 뒤 기능별로 검토한다. |

각 구현 PR은 관련 ID, 현행과 변경 후 사용자 흐름, 저장·프로토콜 호환성, 오류·취소·재시작 동작, 실제 실행한 검사와 미실행 항목을 연결한다. UI/CLI가 같은 정책을 사용하도록 [확장 가이드](21-extending.md)를 따른다. 위 단계는 고정된 일정이나 모든 항목의 일괄 구현을 뜻하지 않는다.

## 6 범위와 보안 원칙

- 기존 worker endpoint·token·Gate·자원 제한을 유지한다. worktree는 코드 변경을 분리하지만 OS 보안 sandbox가 아니며 full pipe의 same-user 한계를 숨기지 않는다. [현재 권한 경계](19-worktree-sessions-orchestration.md#20-권한-경계와-제한-워커-채널-o2-22-tm-20-브랜치-linejinrm-o2)를 따른다.
- 기능 preview·프로필·템플릿·이슈 본문은 이후의 권한 확대·merge·배포를 포괄 승인하지 않는다. 워커의 텍스트 보고와 daemon이 기록한 실행 결과를 구분한다.
- 원문 로그·미저장 코드·의견 초안·복구본은 민감정보를 포함할 수 있다. 기본 로컬 보존, 제한된 양과 기간, 선택적 export·명시적 폐기를 설계한다.
- 네이티브 채팅·내장 브라우저·다국어 UI·클라우드 동기화·공개 relay 운영·자동 merge는 이번 기본 기능 목록에 넣지 않는다. 기존 MVP 제외·원격 단계의 범위를 바꾸려면 별도 제품 결정을 한다.
- 원격·모바일은 해당 단계의 실제 환경 검증과 [위협 모델](22-threat-model.md)을 따른다. 이 로컬 소스의 기능 제안으로 최신 원격 구현이나 인터넷 출시 완료를 주장하지 않는다.
- 서명 없는 패키지 생성, 공인 서명 완료, SignPath 심사 승인을 구별한다. 공개 배포·신청은 [설치와 서명 준비](install/signpath.md)의 별도 절차다.

## 7 후속 검증 기록

초기 문서 정리에서는 코드와 기존 테스트 assertion을 검토했으며 새 장애 재현·성능 측정·실제 agent 실행·전체 cargo test는 하지 않았다. 초기 로컬 rustc 실행에는 Smart App Control 오류 4551이 있었다. 후속 워커의 실제 구현·검사 결과는 [작업 실행 기록](25-improvement-execution.md)에 별도로 남긴다. 기존 정책 검사 docs·boundaries·workspace 통과와 위에 연결한 원격 CI·패키징 결과는 각각의 범위로만 사용한다.

다음 검토 때는 수정 commit과 회귀 시험을 각 ID에 연결하여 상태를 갱신한다. 기능 항목은 제안→범위 확정→구현→검증의 단계를 구분하고, 코드가 추가된 것만으로 사용자 흐름의 검증 완료로 바꾸지 않는다.
