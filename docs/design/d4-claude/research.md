# D4 조사 — IDE·도구들의 디자인 언어 (Claude 독립안)

2026-11-09. 공개 자료만 사용했습니다(공식 문서, 디자인 시스템 페이지, 공식 블로그·제품 페이지의 스크린샷 설명). 제품 자산, CSS, 아이콘은 가져오지 않았습니다. 아래 수치 중 출처를 확인한 것은 **(확인)**, 기억이나 일반적 관찰에 기댄 것은 **(관찰)**으로 표시했습니다. 목표는 "무엇이 세련돼 보이게 하는가"를 원리로 뽑아내는 것이고, 특정 제품의 모양을 1:1로 따라 하는 것은 목표가 아닙니다.

## 0. 현재 Pod 진단 (baseline 1440×960, 150 %)

코디네이터가 짚은 문제를 직접 확인했습니다. 정정과 추가 사항도 함께 적습니다.

| 문제 | 확인 결과 |
|---|---|
| 큰 행, 약한 위계 | 작업자 행 간격이 약 60 px(150 %) = **40 논리 px**입니다(`HEIGHTS` 32 + 여백). 작업 제목(15 px)과 작업자 행(15 px)의 무게가 거의 같습니다. 두 줄짜리 작업 머리(제목 + `pod/task-000 · 작업 1 · 응답 1 · 완료 1`)가 행마다 반복되어 화면이 길어집니다. |
| 테두리 텍스트 버튼이 많음 | 사이드바 머리에 5개(격자, +작업, +터미널, +그룹, 에이전트)가 있고 **두 줄로 접힙니다**. 타이틀바에는 2개(명령·터미널 검색, 설정), 상태 표시줄에는 2개(상태, 알림)가 있습니다. "Pod"가 타이틀바와 사이드바에 **두 번** 나옵니다. |
| 아이콘으로 쓰인 이모지 | **정정**: 🔎는 아이콘이 아니라 픽스처 작업 이름의 일부입니다(`source.rs:215`, 이모지 렌더 시험용). 실제로 이모지를 아이콘처럼 쓰는 곳은 리뷰의 💬입니다(`review.rs:1082, 1432, 1559`). 그 밖의 유니코드 기호: 리뷰 툴바의 ↑ ↓ ◀ ▶ ⟳(`review.rs:987–1019`), `gates.rs:356`의 ⟳, `strings::COMPARE` "⟳ 비교", `pr_panel`의 ✓. |
| 에이전트 트리의 중복 꺾쇠 | `tree.rs:315`가 이름 앞에 `"› "`를 붙이고 행에도 `>` 꺾쇠가 있어 `> ›`가 됩니다. `tree.rs:397`의 ▸/▾가 별도 열을 차지합니다. 노드 표시는 ▣ 글리프이고, 행마다 두 번째 줄(`powershell · fixture-0`)이 있어 행 높이가 77 px(150 %)입니다. |
| 리뷰 툴바 | 텍스트 토글 4개(나란히/한 줄로/펼치기/줄바꿈)와 기호 5개, `파일 ✓`·`의견 ✓`가 한 줄에 같은 무게로 놓여 있습니다. 오른쪽 의견 칸의 안내 문장이 오른쪽 끝에서 잘립니다("+를 누르세"). 오류는 패널 본문에 빨간 글자 한 줄(`변경 사항을 읽지 못했습니다: …`)로만 나오고 아이콘이나 동작 버튼이 없습니다. |
| 상태 표시줄 | `podd UI fixture (read only) · pid 0  터미널 300 · 실행 300 · 패널 0  ● 작업 49 ▲ 응답 50 ✓ 완료 51  작업 100  ⚑ 승인 요청 없음  [상태] [알림 0]`처럼 묶음 없이 이어집니다. 아이콘이 글리프(●▲✓⚑)여서 상태 체계의 SVG 아이콘과 서로 다릅니다. |
| 빈 화면 | 카드 하나, 제목 28 px, 같은 너비의 버튼 두 개(파랑 채움 + 테두리)입니다. 설명이 두 줄로 어색하게 접힙니다("있 / 습니다"). |
| 추가로 본 것 | 선택 행이 표시되지 않습니다(workspace에 선택 상태가 없음). 대화상자의 프로그램 선택이 테두리 버튼 4개입니다(분할 제어가 아님). 입력 필드 테두리, 버튼 테두리, 카드 테두리가 모두 같은 회청색이라 위계가 없습니다. 현재 토큰은 대비를 모두 통과합니다(`tools/visual/contrast.py` 36/36 + 36/36). 문제는 색이 아니라 **밀도, 위계, 크롬의 양**입니다. |

## 1. 도구별 요약

### VS Code (Default Dark/Light Modern, Codicons)
- **밀도**: 목록 행 22 px, 탭 35 px, 상태 표시줄 22 px **(관찰)**. 높은 밀도인데도 읽기 쉬운 이유는 행마다 정보가 한 줄뿐이기 때문입니다.
- **면/테두리**: 2023년 Modern 테마부터 무채색 회색 면 2–3단계에 1 px 경계선을 씁니다. 파랑은 포커스, 주 버튼, 활성 탭 윗선에만 씁니다 **(관찰)**.
- **아이콘**: Codicons. 16 px 그리드의 단색 아이콘 폰트입니다. 저장소 라이선스는 **CC-BY-4.0 + 코드 MIT**입니다 **(확인: github.com/microsoft/vscode-codicons)**. 아이콘 자체에 저작자 표시 의무가 붙으므로, "의존성은 Apache/MIT만"이라는 Pod 원칙에 맞지 않습니다.
- **상태/탭/패널**: 활동 막대(아이콘만) → 사이드바 → 편집기 → 패널 순서입니다. 상태는 상태 표시줄의 "아이콘 + 숫자" 묶음으로 보여 줍니다. 명령 센터는 타이틀바 가운데의 알약 모양 검색입니다.
- **세련된 이유**: 강조색 하나만 쓰고, 테두리는 1 px로 일관되며, 아이콘 크기가 모두 같습니다.
- **Pod 적합성**: 타이틀바 명령 알약, 상태 표시줄의 아이콘+숫자 묶음, "강조색 = 포커스와 주 동작" 규칙은 그대로 맞습니다. 활동 막대는 Pod 화면 수(작업/리뷰/에이전트/설정)에 비해 과합니다.

### JetBrains New UI (2022–) / Islands 테마 / Fleet
- **밀도**: 기본 모드와 **Compact Mode**가 따로 있습니다. 컴팩트 모드는 "툴바와 도구 창 머리의 높이, 간격, 여백, 아이콘·버튼 크기"를 줄입니다 **(확인: jetbrains.com/help/idea/new-ui.html)**.
- **글꼴/아이콘**: 모든 OS에서 Inter를 씁니다. 새 아이콘 세트는 "더 구별되는 모양과 색"을 목표로 합니다 **(확인)**. 아이콘은 윤곽선 위주이고 색은 의미가 있을 때만 씁니다.
- **크롬**: 메인 툴바에 프로젝트, VCS, 실행 위젯을 두고, 드물게 쓰는 기능은 단계적으로 드러냅니다(progressive disclosure, 공식 문구) **(확인)**. 도구 창은 "줄무늬(stripe)"의 아이콘으로 엽니다.
- **Islands/Fleet**: 패널을 둥근 "섬"으로 띄우고 패널 사이에 간격을 둡니다 **(관찰)**. → 아래 방향 B의 참고점입니다.
- **Pod 적합성**: 기본은 컴팩트, 선택은 편안함이라는 밀도 이원화가 맞습니다. 툴바를 아이콘으로 줄이는 것도 맞습니다. 메뉴 막대와 위젯이 많은 구성은 Pod 규모에 과합니다.

### Zed
- GPUI로 만든 편집기로, **Pod와 같은 렌더러**입니다. 테마는 surfaces, borders, scrollbars, terminal 등 **16개 범주**의 UI 색으로 구성됩니다 **(확인: zed.dev/blog/theme-builder)**. 타이틀바 항목은 설정으로 끄고 켭니다 **(확인: zed.dev/docs/visual-customization)**.
- **관찰**: 경계선이 얇고 대비가 낮습니다. 패널 머리가 낮고, 탭은 텍스트 위주이며, 상태 표시줄은 아이콘만 두는 경향입니다.
- **Pod 적합성**: GPUI에서 이 정도 밀도를 무리 없이 낼 수 있다는 근거입니다. Zed 앱 코드와 자산은 GPL/AGPL이므로 **보지 않고 가져오지 않습니다**(원칙대로).

### Xcode / Nova / Sublime Text
- **Xcode** (관찰): 툴바 가운데의 "활동 표시(activity viewer)" 알약 하나가 빌드와 실행 상태를 요약합니다. 내비게이터는 아이콘 탭으로 바꿉니다. SF Symbols는 굵기를 글자 굵기에 맞춥니다. → 아이콘 굵기를 글자와 맞추는 원칙, "가운데 상태 알약" 패턴.
- **Nova** (관찰): macOS 기본 컨트롤을 쓰고 사이드바 면이 반투명입니다. 프로젝트마다 색을 줍니다. 장식이 풍부해 Windows 우선인 Pod에는 맞지 않습니다.
- **Sublime** (관찰): 크롬이 거의 없습니다. 명령 팔레트(Ctrl+Shift+P) 패턴의 원조입니다. 탭과 미니맵뿐입니다. → "크롬은 조용히, 내용이 먼저"라는 원칙의 극단입니다.

### Cursor / Windsurf (AI 편집기, VS Code 계열)
- (관찰) VS Code 골격 위에 오른쪽 **에이전트/채팅 패널**을 둡니다. 변경은 편집기 안에서 인라인 diff로 수락·거부합니다. 에이전트 상태는 패널 머리와 탭 점으로 보여 줍니다. "몇 개의 에이전트가 무엇을 기다리는가"를 한눈에 보는 화면은 약합니다. 대체로 한 에이전트에 한 대화입니다.
- **Pod 적합성**: 리뷰 의견을 에이전트에 보내는 흐름은 비슷합니다. Pod의 차별점인 **여러 에이전트 + 여러 터미널**은 이 도구들이 다루지 않으므로, 상태 요약을 Pod가 직접 설계해야 합니다.

### Warp / Windows Terminal
- **Warp**: 출력이 블록 목록이고, 탭 표시와 블록 선택에만 **강조색 속성**을 씁니다 **(확인: warp.dev 테마 설계 글)**. **Compact mode**는 블록 사이 간격을 줄입니다 **(확인: docs.warp.dev)**.
- **Windows Terminal**: 탭이 타이틀바 안에 있고, 1.17부터 Mica를 지원합니다 **(확인: microsoft/terminal #1375)**. Cascadia 글꼴과 Segoe Fluent Icons를 씁니다 **(관찰)**.
- **Pod 적합성**: 터미널 면은 장식 없이 평평하게 두고 강조색은 선택과 포커스에만 씁니다. Windows 캡션 버튼은 46 px 폭의 OS 규약을 따릅니다. Mica(반투명)는 GPUI의 Windows 백엔드에서 대비를 보장하기 어려워 쓰지 않습니다.

### Linear / Raycast / Arc (다듬어진 제품 도구)
- **Linear**: 테마 변수를 98개에서 **세 개(base, accent, contrast)**로 줄이고 LCH로 생성합니다. contrast 값으로 고대비 테마도 만듭니다 **(확인: linear.app/now/how-we-redesigned-the-linear-ui)**. 관찰: 13 px 안팎의 촘촘한 목록, 상태마다 모양이 다른 작은 원형 상태 아이콘, 키보드 우선 설계, 아주 옅은 경계선.
- **Raycast** (관찰): 목록 항목이 "아이콘 + 제목 + 부제 + 오른쪽 부속 정보(accessories)" 문법을 따르고, 동작 패널과 단축키 힌트가 일관됩니다. → Pod의 사이드바 행 문법(상태 + 제목 + 오른쪽 메타)에 맞습니다.
- **Arc** (관찰): 바깥 틀(색이 있는 프레임) 안에 내용이 둥근 카드로 떠 있습니다. 탭은 사이드바 세로 목록입니다. → 레이어형(B)의 참고점입니다. 장식성이 높아 오래 쓰는 터미널 앱에는 피로할 수 있습니다.

## 2. 공통으로 뽑은 원리

1. **강조색은 하나, 그리고 드물게.** 포커스, 선택, 주 동작에만 씁니다. 상태색은 별도 체계이고, 채도를 낮추되 모양(아이콘)으로도 구별합니다.
2. **크롬은 아이콘, 내용은 글.** 반복 동작은 툴팁이 달린 아이콘 버튼으로 둡니다. 텍스트 버튼은 화면당 주 동작 1–2개만 둡니다.
3. **한 행에 한 줄.** 보조 정보는 오른쪽 메타(Raycast식 부속 정보)나 hover/선택 때만 보입니다.
4. **면의 단계 3–4개에 1 px 경계선**(A식) 또는 **면 + 그림자**(B식). 둘을 섞으면 지저분해집니다.
5. **밀도는 모드로 나눕니다**(JetBrains Compact, Warp Compact). 기본은 컴팩트로 둡니다.
6. **아이콘 한 계열, 한 굵기, 한 크기 격자.** 글자 굵기와 아이콘 선 굵기를 맞춥니다(Xcode).
7. **테마는 적은 변수에서 생성**(Linear)해야 다크, 라이트, 고대비가 같이 유지됩니다.

## 3. Pod에 맞는 것과 맞지 않는 것

| 맞음 | 맞지 않음 |
|---|---|
| 타이틀바 명령 알약(Ctrl+K), 상태 표시줄 아이콘+숫자 묶음 | 활동 막대 + 여러 사이드 뷰(화면 수에 비해 과함) |
| 컴팩트 기본 + 편안함 옵션 | Mica/아크릴 반투명(대비 보장 어려움, GPUI Windows 지원 불확실) |
| 상태마다 모양이 다른 아이콘 + 한국어 라벨(기존 v1 상태 체계 유지) | 색만으로 상태 구분 |
| 1 px 경계선 + 면 3단계(GPUI에서 싸고 150 %에서 선명) | 큰 그림자, 흐림(blur) 위주 깊이 표현(패널마다 GPU 비용과 경계 번짐) |
| Lucide(이미 ISC로 고정 반입) | Codicons(아이콘에 CC-BY-4.0), Zed 자산(GPL) |
| 키보드 힌트(kbd) 표시 | macOS 전용 관례(SF Symbols, 신호등 버튼) |

**한국어 주의점**: Segoe UI Variable에는 한글이 없어 맑은 고딕으로 대체됩니다. 13 px에서 한글 획이 Inter·Segoe보다 커 보이므로 **줄 높이는 20(1.54)**을 유지하고, 12 px 미만은 쓰지 않습니다. 굵게(600)는 제목과 수치에만 쓰고, 한글 본문은 400/500으로 둡니다.
